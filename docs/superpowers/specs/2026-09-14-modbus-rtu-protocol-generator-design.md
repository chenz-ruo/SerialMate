# SerialMate v1.1.1 Modbus RTU 协议数据生成设计

## 目标与范围

在现有“协议数据生成”Card 内实现第一版 Modbus RTU 请求帧生成，支持功能码 `03`、`04`、`06`、`10`。生成器负责严格校验、标准 CRC-16 计算和统一 HEX 输出；UI 负责输入、动态字段、复制以及把结果写入指定自定义数据槽位。

本阶段不实现其他协议，不发送生成结果，不改变串口核心逻辑，也不修改现有主界面宽度、Card 高度、Card Gap、响应式三列规则、自定义数据 16 槽结构或通信记录 8/16/32 bytes 布局。

## 模块边界

新增 `ProtocolGenerator.h/.cpp`，定义 UI 可使用的协议请求、生成结果和错误结果接口。该层只负责选择当前协议生成器，使以后新增协议时无需把协议算法写进 `main.cpp`。

新增 `ModbusRtuGenerator.h/.cpp`，实现 Modbus RTU 参数校验、请求 PDU/ADU 组装、CRC-16 以及规范化 HEX 输出。模块不依赖 HWND、剪贴板、串口或应用状态，可由单元测试直接调用。

`main.cpp` 只负责创建和排列协议 Card 内部控件、读取输入、调用 `ProtocolGenerator`、显示结果、复制结果和写入自定义槽位。协议算法和参数规则不得复制到 UI 层。

## 数据模型与生成结果

公共请求包含：协议类型、功能码、从机地址、地址、寄存器数量、写入值和写入 word 列表。动态表单会根据功能码提供其中适用的字段。

生成成功返回：

- 完整帧字节数组；
- 规范化 HEX 字符串；
- CRC 低字节和高字节；
- 帧总字节数。

生成失败返回明确中文错误，不产生部分帧，UI 的只读结果框保持原结果不变，状态行显示错误。

## Modbus RTU 规则

所有工程输入均为 HEX，可接受大小写，字段前后空白可忽略。地址、数量和值按 16 位大端写入帧。HEX 字符串输出统一为大写、每字节两位、空格分隔。

范围如下：

- 从机地址：`01–F7`；
- 16 位地址：`0000–FFFF`；
- `03/04` 寄存器数量：`0001–007D`，即 1–125；
- `06` 写入值：`0000–FFFF`；
- `10` 寄存器数量：`0001–007B`，即 1–123；
- `10` 写入数据：每个 word 必须恰好四个 HEX 字符，可用空白分隔；word 数必须与寄存器数量相等。

`10` 的 byte count 为 `quantity × 2`。非法 HEX、空字段、越界字段、不完整 word、数量与数据不匹配均禁止生成。

CRC 使用标准 Modbus RTU CRC-16：初值 `0xFFFF`，多项式 `0xA001`，逐字节处理，最终低字节在前、高字节在后附加到帧。

## 协议 Card UI

保持既有 `protocolCard` Rect 不变。内部使用现有 Card padding 和控件视觉高度建立紧凑表单：

1. 协议类型下拉框，第一版固定为 `Modbus RTU`；
2. 同行显示从机地址与功能码；
3. `03/04` 显示起始地址和寄存器数量；
4. `06` 显示寄存器地址和写入值；
5. `10` 显示起始地址、寄存器数量和写入数据；
6. 生成按钮和“填入自定义...”按钮；
7. 只读 HEX 结果框和复制按钮；
8. Card 内状态行，成功时显示字节数和 CRC，例如 `状态：8 bytes / CRC C4 0B`。

所有协议子控件在启动时创建。功能码切换仅重新设置标签并 Show/Hide 适用控件，不 Create/Destroy，不参与主界面 Geometry 计算。右侧扩展列未显示时，协议控件随现有扩展区隐藏规则一并隐藏；渐进揭示时由现有 viewport 裁剪。

## 填入自定义槽位

“填入自定义...”仅在已有有效生成结果时可用。点击后弹出 `1–16` 菜单；选择 N 后只把规范化 HEX 字符串写入 `CustomDataN` 对应 Edit，并复用现有自定义数据变更路径更新内存状态。

该操作不得：

- 自动发送；
- 修改主数据发送框；
- 修改十六进制发送勾选状态；
- 修改其他自定义槽位。

如果十六进制发送未开启，协议 Card 状态行显示非阻塞提示：`已填入自定义N；发送时请启用“十六进制发送”`。开启时显示 `已填入自定义N`。

## 复制行为

复制按钮仅复制只读结果框中的规范化 HEX 字符串。没有有效结果时不清空系统剪贴板，并在协议 Card 状态行提示先生成数据。复制成功显示非阻塞状态。

## 测试与验收

新增 `ProtocolGeneratorTests`，至少覆盖：

- CRC 已知向量；
- `03`、`04`、`06`、`10` 的完整标准帧；
- 从机地址非法；
- 16 位地址非法；
- `03/04/10` 数量为零或超上限；
- 非法 HEX；
- `10` 数据存在半个 word；
- `10` 数量与数据 word 数不一致。

UI 自动测试覆盖：

- 四个功能码的动态字段切换；
- 生成结果和状态显示；
- 复制得到精确规范化 HEX；
- 写入指定槽位且其他 15 槽、主发送框、十六进制勾选状态不变；
- 无有效结果时禁止复制和填入。

回归验收必须重新运行现有全量测试、Geometry 测试、UI 冒烟测试和 COM7 实际回环。任何现有主 Geometry 数值或响应式行为变化均视为本阶段失败。
