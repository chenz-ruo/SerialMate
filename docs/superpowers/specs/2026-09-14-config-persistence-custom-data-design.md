# SerialMate v1.1.1 隐藏配置与自定义数据设计

## 目标与范围

本阶段增加隐藏配置持久化和 16 个自定义数据槽的正式发送能力。版本继续保持 v1.1.1。

本阶段冻结现有主界面 Geometry，不调整左、中、右三列宽度、Card 尺寸与间距、顶部按钮位置、渐进揭示规则或 8/16/32 bytes 自适应规则。本阶段不实现 Modbus RTU，不保存窗口位置、窗口尺寸、通信记录、收发计数、主发送编辑框或右侧展开状态。

## 模块边界

新增 `ConfigStore.h` 和 `ConfigStore.cpp`。`ConfigStore` 只负责：

- 确定并保持本进程唯一的配置路径；
- 读取、解析和校验配置；
- 保存本实例真正修改过的槽位；
- 跨进程合并、原子替换和隐藏属性处理。

`Application` 继续负责控件和发送交互。它持有 16 个槽位文本以及逐槽 dirty 标记，通过 `ConfigStore` 加载和保存，但不自行实现文件格式或路径选择。

## 数据模型和文件格式

配置版本固定为：

```ini
ConfigVersion=1
```

自定义数据固定为：

```ini
CustomData01=
CustomData02=
...
CustomData16=
```

配置文件采用 UTF-8 无 BOM 和 CRLF。解析每行时只按第一个 `=` 分隔，因此值中的空格、中文、反斜杠和额外的 `=` 均原样保留。当前槽位仍是单行编辑框，不引入多行转义协议。

每个槽位最多保存 4096 个 `wchar_t`。UI 使用 `EM_SETLIMITTEXT` 阻止继续输入，加载和发送时再次检查。超过上限、UTF-8 无法解码或字段结构损坏时，只忽略该字段并使用空字符串；其他可读字段继续加载。未知字段和未知 `ConfigVersion` 不阻止启动。

## 稳定路径选择

候选路径为：

```text
Primary  = <ExeDir>\SerialMate.ini
Fallback = %LOCALAPPDATA%\SerialMate\SerialMate.ini
```

启动时一次性按以下顺序决定保存路径，之后整个进程不再改变：

1. Primary 已存在且其目录可写：读取并使用 Primary。
2. Primary 已存在但其目录不可写：先读取 Primary 作为基础；若 Fallback 存在，则 Fallback 中存在且有效的字段覆盖 Primary；保存路径固定为 Fallback。
3. Primary 不存在、Fallback 已存在：读取并使用 Fallback。
4. 两者均不存在：通过在 Primary 同目录创建并删除临时探测文件确认可写；成功则使用 Primary，否则创建 Fallback 目录并使用 Fallback。

目录可写探测使用唯一临时文件，不修改正式配置。路径一旦确定，后续保存失败不会在运行中切换到另一路径。

## 加载与 dirty 状态

应用创建 16 个槽位控件后加载配置。加载期间通过内部抑制标记避免程序调用 `SetWindowTextW` 触发 `EN_CHANGE` 并错误标记 dirty。

用户编辑某个槽位时：

1. 更新对应内存文本；
2. 只标记该槽位 dirty；
3. 不立即写磁盘。

不可见的槽位控件仍然在启动时创建，其文本、内存值和 dirty 状态不依赖当前窗口高度。正常退出时保存一次。若配置尚不存在，即使没有 dirty 槽位，也写出包含版本和 16 个字段的初始配置。

## 多实例合并与原子保存

为每个规范化绝对配置路径生成稳定的 Windows 命名互斥锁名称。锁位于当前用户的 `Local` 命名空间，避免不同配置路径相互阻塞。

保存流程为：

1. 获取路径对应的命名互斥锁；
2. 在锁内重新读取磁盘上的最新配置；
3. 仅用本实例 dirty 的槽位覆盖磁盘值；
4. 写入与正式文件同目录的 `SerialMate.ini.tmp.<PID>`；
5. 调用 `FlushFileBuffers` 并完整关闭临时文件；
6. 在替换前保存目标文件已有属性；
7. 目标已存在时使用 `ReplaceFileW`，不存在时使用带 `MOVEFILE_WRITE_THROUGH` 的 `MoveFileExW`；
8. 将替换前保存的属性与 `FILE_ATTRIBUTE_HIDDEN` 按位 OR 后设置到新目标文件；
9. 释放互斥锁。

临时文件与目标位于同一目录，保证替换不跨卷。任何失败都清理本实例临时文件，不破坏原配置。不同实例修改不同槽位时能合并；同时修改同一槽位时最后一次成功写入生效。

## 保存失败处理

配置错误不能导致应用启动或退出崩溃。正常退出保存失败时只提示一次“自定义数据配置保存失败。”，并写入现有日志通道；不会循环弹窗。若启动路径选择阶段成功使用 Fallback，不提示失败。

## 自定义数据与统一 TX 链路

当前 `BuildSendData` 改为以文本参数构建数据，编码、HEX 解析和 CR/LF 追加只保留一套实现。发送执行也保留一个公共入口，统一负责：

- 串口状态检查；
- 发送队列提交；
- TX 计数；
- 通信记录；
- 结构化日志；
- 错误处理。

数据来源分为主编辑框、定时发送和自定义槽。主发送仍读取主编辑框；定时发送仍使用主编辑框；自定义按钮直接传入对应槽位文本，不再临时覆盖主编辑框。

自定义数据完全复用当前十六进制、UTF-8、GBK、ASCII、CR 和 LF 设置。点击自定义发送按钮时，如果主编辑框正在定时发送，先停止定时发送，再将该槽发送一次。自定义槽本身不增加定时、编码或换行设置。

自定义数据解析或编码失败时不修改槽位文本，也不进入串口队列。错误标题包含槽位序号，例如“自定义数据 5 格式错误”，正文附带现有 HEX 或 TextCodec 错误信息。

## 更新兼容性

配置文件位于 EXE 目录或 LocalAppData，独立于更新下载和 EXE 替换。现有更新器只允许替换程序文件，不删除 `SerialMate.ini`，也不清理 `%LOCALAPPDATA%\SerialMate`。后续版本继续读取 `ConfigVersion=1` 数据。

## 测试策略

新增 `ConfigStoreTests`，使用独立临时目录和真实 Windows 文件 API，覆盖：

1. 无配置文件和首次创建；
2. `ConfigVersion=1`；
3. 16 个槽位、空字符串、中文和 HEX 文本；
4. 4096 字符边界和超长损坏字段；
5. 损坏 UTF-8、未知版本、未知字段和局部字段损坏；
6. Primary、Fallback 及 Primary 不可写路径选择；
7. 临时文件写入、原子替换和失败后原文件保留；
8. Hidden 属性与其他属性保留；
9. 两个实例修改不同槽位时的合并；
10. 两个实例修改同一槽位时最后成功写入者生效。

扩展 UI 测试：在隔离目录中复制并启动被测 EXE，写入 CustomData01、CustomData08 和 CustomData16，正常退出后重新启动，拖宽窗口并验证三个槽位恢复，包括首次启动时不可见的槽位。

扩展真实 COM loopback 测试：分别用主发送框和自定义槽发送 ASCII、UTF-8 中文、GBK 中文、HEX 以及 CR/LF 组合，比较实际 RX/TX 字节、计数和通信记录结果完全一致。

所有现有 `ResponsiveUi`、`UiGeometry`、`AdaptiveRecordLayout` 测试必须继续通过。先记录 `CommRecord` 和 `CommView` 性能用例的实际耗时与阈值；若存在原有不稳定失败，本阶段单独报告，不通过放宽阈值掩盖。

## 验收条件

- 版本仍为 v1.1.1；
- 配置路径稳定，文件为 UTF-8 无 BOM、CRLF，并带 Hidden 属性；
- 16 个槽位跨重启保存，不可见槽位不丢失；
- 多实例编辑不同槽位不会互相覆盖；
- 自定义数据直接使用统一 TX 链路，主编辑框内容不被改写；
- HEX、UTF-8、GBK、ASCII、CR/LF 行为与主发送一致；
- 当前 Geometry 和 8/16/32 bytes 行为不变；
- 本阶段所有新增测试及现有回归测试通过；
- 不实现 Modbus RTU。
